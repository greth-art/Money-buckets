# Data contract (v1)

`data/picks.json` is a versioned envelope: `{ schemaVersion: 1, isDemo: true, picks: StockPick[] }`. The backend endpoint returns the same contract with `isDemo: false` only after validating provider data. Provider envelopes also require `editorialIsDemo` (currently always `true`): this flags the unchanged illustrative rankings, buckets, entry zones, thesis, and risks independently from provider market data.
`src/model.js` provides JSDoc types, runtime validation, filtering, and target-upside calculation. `src/repository.js` owns data loading; UI modules do not fetch providers directly.

| Field | Meaning / constraint |
| --- | --- |
| id | Stable unique pick identifier; not necessarily the ticker |
| rank | Unique positive editorial rank; unrelated to selected display sort |
| symbol, companyName | Display identity; a future provider adapter should add exchange and provider identifiers |
| currency | USD for v1; all amounts in a pick share this currency |
| bucket | core, growth, or speculative; organizational tags, not risk guarantees |
| quote | Positive price, ISO timestamp with timezone (`asOf`), source attribution, and optional `freshness` (`live`, `delayed`, or `stale`) |
| entryZone | Positive low/high research entry range, low ≤ high |
| analystTargets | Nullable snapshot: low ≤ average ≤ high; nullable analystCount/rating when the provider omits recommendations; asOf; source; positive integer horizonMonths; optional freshness |
| recommendation | Provider picks require this field: null for an empty recommendation array, otherwise a snapshot with analystCount, rating, asOf, source, and optional freshness. It remains available even when targets are absent. |
| thesis, risks | Research rationale and nonempty array of risks |
| updatedAt | ISO timestamp with timezone for the editorial pick |

Ratings: strong-buy, buy, hold, sell, strong-sell. Missing target coverage is `analystTargets: null`, never zero-filled. An empty target object `{}` means absent target coverage; an empty recommendation array `[]` means absent recommendation coverage. Error envelopes, unexpected shapes, partial target values, invalid counts, and mismatched symbols fail validation. If a target exists but recommendation coverage does not, `analystCount` and `rating` are null. The average is the provider's consensus, not the midpoint of low/high. The target's `analystCount` and `rating` are backward-compatible aliases of the separate `recommendation` snapshot and must match it. The UI displays recommendation provenance independently. The Finnhub adapter's `analystCount` is the sum of strong-buy, buy, hold, sell, and strong-sell counts in the latest recommendation snapshot, selected by its validated `period` rather than array order; its rating is the nearest category to the weighted mean (5 to 1, with exact ties rounded toward sell). A latest snapshot with all zero counts retains its date/source but has null rating and count. This recommendation population may differ from the price-target population.

Upside = `(analystTargets.average / quote.price - 1) * 100`. It is a target comparison, not a probability, expected return, or risk-adjusted score. Missing targets sort last by upside. Quotes, targets, and recommendations carry separate timestamps because their update schedules differ. Timestamps normalize to UTC ISO strings; dates without time use UTC midnight, numeric timestamps use Unix seconds, and full datetime strings require an explicit timezone. Invalid calendar dates and timestamps more than 60 seconds into the future are rejected. Timezone-less datetimes are rejected rather than guessed. Quote freshness is `live` at up to 15 minutes old, `delayed` up to 24 hours, then `stale`; analyst targets and recommendations are snapshots and marked `delayed` up to 30 days, then `stale`. If the provider cannot be reached but a cached response exists, all cached provider fields are marked stale. Browser labels are recalculated every 30 seconds; data refreshes every five minutes while visible and on tab reactivation. A browser refresh failure also marks retained provider fields stale. Only a successful refresh can clear a forced-stale state. These are application thresholds based on timestamps, not a guarantee of exchange-level real-time service.

## Provider adapter

The optional backend uses Finnhub's `/quote`, `/stock/price-target`, and `/stock/recommendation` endpoints for the five US symbols in the fixture. API credentials are read only from the server's `FINNHUB_API_KEY` environment variable and sent via the `X-Finnhub-Token` header. They are absent from request URLs, returned datasets, static builds, and client-facing errors. Without the key the backend returns the demo fixture; a static-only host falls back to that same fixture. Responses time out after five seconds including body consumption. Transient network/body failures and server errors without Retry-After retry at most once; malformed JSON and ordinary client errors do not retry. HTTP 429 and Retry-After responses establish a shared cooldown for the full requested delay (delta seconds or HTTP date), with a minimum of 60 seconds. Other failed batches also establish a 60-second cooldown. During cooldown callers get a stale cached dataset or an unavailable response; no new provider calls are made. Successful snapshots are cached in memory for five minutes. Concurrent loads share a batch, and all sibling requests settle before releasing the batch lock. A failure in any endpoint rejects the whole refresh rather than mixing partial results with old or demo values.

Finnhub advertises a $0 free plan with a 60-request-per-minute limit and US stock coverage; real-time access and use/redistribution rights depend on the account's exchange entitlements and applicable Finnhub terms. The free tier is for personal/non-commercial use; commercial display requires confirming and obtaining the appropriate license. Quote delay is not assumed from plan name: the UI classifies freshness from the provider timestamp, and users must verify entitlements and licensing before use. Current terms can change; consult [Finnhub pricing](https://finnhub.io/pricing), [API documentation](https://finnhub.io/docs/api), and [terms](https://finnhub.io/terms-of-service).

Future persistence: normalize into `stocks` (identity), `picks` (rank, bucket, thesis, entry zone), `quote_snapshots`, and `analyst_target_snapshots`, linked by stock ID. Retain historical snapshots rather than overwriting them. Add server-side validation, currency normalization, and migrations when introducing a database.
